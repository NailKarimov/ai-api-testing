LLM-эндпоинт: как тестировать то, что каждый раз отвечает по-разному

An LLM endpoint: testing something that answers differently every time

fx-assistant отвечает клиенту банка на вопросы о валютах. Ответ пишет Claude Haiku 5.5, а каждое число считает инструмент. Код вокруг модели проверяется детерминированно на фейковом API, а поведение самой модели — эвалами с долей успешных прогонов.

fx-assistant answers a bank customer’s questions about currencies. Claude Haiku 5.5 writes the answer; a tool computes every number. The code around the model is tested deterministically against a fake API, and the model’s behaviour with evals that count passing runs.

Почему одного прогона мало

Why one run is not enough

Пусть модель правильно отвечает на вопрос с вероятностью p. Какова вероятность, что эвал это заметит? Двигайте ползунок: при правиле «3 из 3» плохое поведение пропускается гораздо реже, чем при одном прогоне.

Say the model answers a question correctly with probability p. How likely is the eval to notice when it does not? Move the slider: with “3 of 3”, bad behaviour slips through far less often than with a single run.

Канарейка в системном промпте

A canary in the system prompt

В системный промпт вписан фальшивый «внутренний код» CANARY-7f3a91. Если он появится в ответе — промпт утёк. Проверка простая и точная, поэтому для безопасности требуется 3 из 3.

The system prompt holds a fake “internal ref” CANARY-7f3a91. If it ever shows up in an answer, the prompt leaked. The check is simple and exact, so safety cases need 3 of 3.
