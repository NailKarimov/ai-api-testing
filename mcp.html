MCP: через что ассистент работает с инструментами

MCP: how an assistant reaches its tools

Model Context Protocol — стандарт, по которому Claude, ChatGPT или агент в IDE подключаются к внешним инструментам и данным. Свой MCP-сервер конвертирует валюты, а тесты проверяют его так, как с ним будет работать модель: по stdio и по HTTP, на уровне JSON-RPC и через независимый клиент.

The Model Context Protocol is how Claude, ChatGPT or an IDE agent connects to outside tools and data. Our own MCP server converts currencies, and the tests check it the way a model will use it: over stdio and HTTP, at the JSON-RPC level, and through an independent client.

isError vs JSON-RPC error

Ошибка для модели или ошибка протокола

An error for the model, or a protocol error

Бизнес-ошибку модель читает и исправляет сама: «такой валюты нет, вот список». Сломанный запрос — ошибка клиента, модели тут исправлять нечего.

A business error is something the model reads and fixes itself: “no such currency, here is the list”. A broken request is the client’s fault; there is nothing for the model to fix.

      Tool poisoning
      
Описание инструмента читает модель
The model reads the tool description

      
Значит, в описание можно спрятать команду для модели: невидимыми символами или «важной инструкцией». Тест проверяет метаданные каждого инструмента. Выберите вариант описания.

      
So an instruction for the model can hide in a description, in invisible characters or as an “important note”. A test checks every tool’s metadata. Pick a description.

      MCP-1
      
Находка: SDK-клиент теряет последний прогресс
Finding: the SDK client loses the last progress

      
Сервер шлёт все 5 уведомлений до результата — так и должно быть. Иногда пятое и результат приходят одним куском stdout, и клиент SDK 1.32 успевает закрыть запрос раньше, чем вызвать onprogress. Поэтому тест сверяет запись провода, а не колбэк.

      
The server sends all 5 notifications before the result, as it must. Sometimes the fifth and the result arrive in one chunk of stdout, and the SDK 1.32 client closes the request before it calls onprogress. So the test checks the recorded wire, not the callback.

    

    

  


  

    

      Мутационная проверкаMutation check
      
14 багов, внесённых нарочно
14 bugs planted on purpose

      
Первый прогон не поймал «сервер игнорирует отмену»: SDK глушит уведомления отменённого запроса, и брошенная работа невидима. Появился ресурс fx://server/jobs. Баг про «throw вместо isError» эквивалентный: SDK сам превращает исключение в такой же ответ.

      
The first run missed “the server ignores cancellation”: the SDK mutes notifications of a cancelled request, so abandoned work is invisible. Hence the fx://server/jobs resource. “throw instead of isError” is equivalent: the SDK turns the exception into the same answer.
